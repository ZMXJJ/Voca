## 2. 产品一句话定义

`Voca` 是一款面向普通用户的本地 AI 语音生成桌面应用。

用户不需要理解 Python、模型、终端或依赖环境，只需要通过图形界面完成：

- 首次初始化
- 参考音频克隆
- 查看和管理生成素材历史
- 结果试听与导出

## 2.1 产品边界

这是一款**纯本地单机应用**，当前设计阶段明确不考虑以下内容：

- 用户系统
- 账号体系
- 登录 / 注册
- 云同步
- 在线社区
- 远程协作
- 多端账户联动

也就是说，前端设计里**不要出现用户头像、账号入口、个人资料、会员体系、消息中心**等典型联网产品元素。

## 3. 当前阶段说明

### 3.1 当前项目阶段

当前处于 `P0 / P1` 之间的前置设计阶段，已经完成：

- PRD
- 技术方案
- API / 事件协议
- 前端代码骨架

目前前端已经有一版**工程骨架页面**，但还不是最终 UI 设计方案。

### 3.2 给设计师的预期

希望设计师输出的是：

1. 一套适合桌面端的整体视觉方向
2. 初始化流程的完整界面方案
3. 主界面的信息架构和交互层级
4. 关键空状态、错误状态、加载状态的表达方式
5. 适合“小白用户”的文案和引导风格

## 4. 目标用户

### 4.1 核心用户

- 想快速体验高质量 TTS 的普通 Mac 用户
- 内容创作者、播客、短视频、配音爱好者
- 需要本地生成、较重视隐私和可控性的个人用户

### 4.2 这类用户的特点

- 不是开发者，不愿意碰终端
- 不理解模型、依赖、环境变量、下载源等技术概念
- 对“进度清晰、失败可恢复、结果可试听”非常敏感
- 更偏好简单明确的操作流，而不是参数堆砌

## 5. 设计目标

### 5.1 设计层面的核心目标

1. 让用户从第一次打开 App 到生成第一段语音，过程足够顺滑。
2. 把复杂的本地部署过程包装成清晰、可理解、可恢复的初始化流程。
3. 让用户在主界面能快速理解“现在可以直接开始克隆声音，历史在哪里，设置在哪里”。
4. 让所有重要状态都“看得见”，尤其是下载、初始化、生成和失败恢复。

### 5.2 设计要避免的问题

- 不要做得像开发者工具
- 不要把技术概念直接暴露给用户
- 不要额外引入与单机产品无关的账号、社交或云端心智
- 不要把过多高级参数放在主路径里
- 不要让错误提示只停留在“失败了”

## 6. 品牌气质与视觉关键词

### 6.1 建议的整体气质

`Voca` 应该看起来：

- 专业但不冷硬
- 有 AI 能力感，但不过度科幻
- 可信、稳定、安静
- 适合内容创作场景

### 6.2 建议关键词

- calm
- intelligent
- premium
- local-first
- creator-friendly
- trustworthy

### 6.3 视觉方向建议

建议以**深色主题优先**为主，同时保留未来浅色主题扩展可能。

原因：

- 语音生成、创作类桌面产品更适合深色工作环境
- 更容易承载“AI + 创作工具”的质感
- 音频波形、状态卡片、进度条在深色背景上表现更稳定

但需要注意：

- 深色不等于压抑
- 需要适当加入柔和高亮色，避免工程化感过强

### 6.4 色彩方向建议

可以考虑：

- 主背景：深灰蓝、深石墨色
- 强调色：青蓝、浅紫、柔和洋红中的一种或两种组合
- 成功态：偏冷绿
- 警告态：暖黄
- 错误态：柔和红

避免：

- 大面积纯黑
- 过度霓虹感
- 太游戏化的高饱和渐变

## 7. 信息架构

### 7.1 一级结构

建议一级结构如下：

1. 初始化流程
2. 主界面框架
3. 声音克隆页面
4. 素材生成历史页面
5. 设置页面

### 7.2 结构原则

- 初始化流程与主界面要明显分层
- 初始化完成后，主界面只保留三个一级区域：`声音克隆`、`素材生成历史`、`设置`
- 默认进入 `声音克隆` 页面，而不是单独再做一个信息密度较低的首页
- 模型、缓存、下载源、日志等内容都收敛进 `设置`
- 任何复杂项都尽量放在次级层级或折叠区

## 8. 页面设计说明

## 8.1 初始化流程

初始化流程是设计重点，决定用户是否愿意继续使用。

### 页面目标

- 告诉用户 App 正在准备什么
- 告诉用户为什么需要等待
- 告诉用户现在是否正常
- 告诉用户如果失败了应该怎么办

### 建议分为 5 个阶段页面

1. 欢迎页
2. 环境检查页
3. 下载页
4. 初始化页
5. 完成页

### 1. 欢迎页

建议包含：

- 产品简介
- 本地运行的价值点
- 首次初始化耗时预期
- 开始按钮

文案语气：

- 轻解释
- 低压力
- 不强调技术细节

例如表达方向：

- “首次使用前，我们会先为你准备运行环境和默认模型”
- “整个过程通常只需几分钟，请保持网络连接”

### 2. 环境检查页

建议包含：

- 芯片架构
- 内存
- 可用磁盘空间
- 网络状态
- 是否满足最低要求

设计重点：

- 尽量用“结果卡片”而不是技术表格
- 每一项都用“正常 / 需要注意 / 不支持”表达
- 不要只给出原始数值，也要给出解释

例如：

- “可用磁盘空间充足”
- “当前网络可用，已准备开始下载”
- “你的设备暂不满足最低要求”

### 3. 下载页

建议包含：

- 当前正在下载什么
- 已下载大小 / 总大小
- 下载速度
- 剩余时间
- 存储目录摘要
- 当前下载源

设计重点：

- 进度信息要非常清楚
- 可以有总进度 + 当前项进度双层表达
- 如果后续接入双下载源，要预留当前源和切换入口的位置

### 4. 初始化页

建议包含：

- 解压
- 安装
- 校验
- 启动服务
- 预热模型

设计重点：

- 更像步骤型流程，而不是单纯进度条
- 每一步最好有“进行中 / 完成 / 失败”的明确状态
- 失败时要能在当前页直接看到恢复建议

### 5. 完成页

建议包含：

- 初始化完成提示
- 简短下一步引导
- 进入主界面的主按钮

## 8.2 主界面框架

初始化完成后，不建议再设计一个独立的“首页”或“仪表盘”页面。

真正的主界面应当直接进入工作区，并且一级结构只保留这 3 个区域：

1. 声音克隆
2. 素材生成历史
3. 设置

### 页面目标

- 用户进入主界面后可以立即开始核心操作
- 降低导航层级
- 避免首页再跳一次工作页的冗余流程

### 主导航建议

建议采用以下两种形式之一：

- 左侧主导航
- 顶部 Tab 导航

无论采用哪种形式，都应满足：

- 一级导航项只有 3 个
- 默认进入 `声音克隆`
- `设置` 是辅助入口，不应抢主路径

### 全局固定信息建议

主界面可以保留一条轻量全局状态区，但不要做成复杂 Dashboard。

建议只保留：

- 当前服务状态
- 资源是否就绪
- 最近错误入口或恢复入口

明确不需要：

- 用户信息
- 账号入口
- 头像区域
- 云同步状态
- 联网消息或通知中心

## 8.3 声音克隆页

这是带参考音频的工作页。

### 页面目标

- 让用户上传参考音频后生成目标声音

### 建议模块

- 参考音频上传区
- 音频文件信息区
- 目标文本输入区
- 可选控制描述区
- 可选参考文本区
- 生成按钮
- 状态提示区
- 结果试听与导出区

### 设计重点

- 上传区需要足够明确
- 上传后需要给出已选文件反馈
- 如果后续支持自动转写，页面里要有“识别中 / 已识别 / 可编辑”的状态设计
- 这是主界面的默认落点页面，视觉完成度和交互完整度应最高

### 高级参数建议

如果保留高级参数，建议统一收纳到折叠区，不进入默认主路径。

可放入折叠区的内容包括：

- CFG
- 推理步数
- 归一化开关
- 降噪开关

## 8.4 素材生成历史页

这是主界面的第二个一级区域。

### 页面目标

- 帮助用户查看本地生成历史
- 快速预览、试听、导出和复用已有结果
- 建立“我之前做过什么”的清晰感知

### 建议模块

- 历史列表区
- 搜索 / 筛选区
- 时间分组或最近排序
- 单条素材卡片
- 详情侧栏或详情面板
- 试听区
- 导出 / 重新使用入口

### 历史条目建议展示的信息

- 生成时间
- 结果时长
- 结果名称或自动生成标题
- 参考音频缩略信息
- 当前状态
- 导出状态

### 设计重点

- 列表要适合高频回看
- 单条素材既要能快速预览，也要能进入更详细视图
- 不能只是一堆文件名
- “最近生成的内容”应该容易找到

### 空状态建议

当还没有历史时，建议提供：

- 空状态插画或简洁说明
- 引导用户去 `声音克隆` 页面开始第一次生成

## 8.5 设置页

### 页面目标

- 提供本地单机应用所需的维护与诊断能力
- 收纳非主路径功能
- 避免技术信息占据主操作区

### 建议模块

- 运行状态摘要
- 当前模型 / 资源状态
- 存储占用
- 下载源设置
- 本地模型导入
- 日志导出
- 缓存清理
- 重新初始化
- 版本信息
- 实验功能开关

### 设计重点

- 设置页不是用户中心
- 设置页也不是开发者控制台
- 应以“本地资源维护”而不是“个人信息管理”为核心

### 明确不需要出现的内容

- 头像
- 昵称
- 账户信息
- 登录状态
- 邮箱绑定
- 云端同步入口

### 危险操作设计要求

- 重新初始化
- 清理缓存
- 删除本地素材

这些操作必须有二次确认，并清楚说明影响范围。

## 9. 关键组件建议

设计师可以优先考虑建立以下基础组件：

- 状态卡片
- 步骤条 / 初始化流程组件
- 下载进度组件
- 音频上传区域
- 文本编辑区
- 任务状态条
- 结果卡片
- 历史列表组件
- 历史条目卡片
- 历史详情侧栏
- 音频播放器
- 导出操作条
- 错误提示条
- 空状态卡片
- 危险操作确认弹窗

## 10. 状态设计要求

这个产品的关键不是“普通页面”，而是“状态非常多”。

设计师需要重点覆盖以下状态：

### 10.1 初始化状态

- 未开始
- 检查中
- 检查通过
- 下载中
- 安装中
- 校验中
- 预热中
- 完成
- 失败

### 10.2 生成任务状态

- idle
- queued
- running
- succeeded
- failed

### 10.3 历史页面状态

- 无历史记录
- 有历史记录
- 正在搜索 / 筛选
- 正在试听
- 导出中
- 删除确认中

### 10.4 资源状态

- 模型未下载
- 模型已下载
- 模型校验中
- 模型可用
- 模型损坏
- 服务未启动
- 服务恢复中

### 10.5 页面空状态

- 尚未上传参考音频
- 还没有任何生成历史
- 尚未初始化完成

### 10.6 错误状态

至少要覆盖：

- 设备不满足要求
- 磁盘空间不足
- 网络不可用
- 下载失败
- 校验失败
- 服务启动失败
- 生成失败

## 11. 文案风格建议

### 11.1 文案原则

- 面向普通用户
- 尽量避免底层术语
- 不要把错误堆栈直接给用户
- 优先给结论，再给动作建议

### 11.2 推荐语气

- 平静
- 清晰
- 不恐吓
- 不卖弄技术感

### 11.3 示例方向

不推荐：

- “模型校验失败，请检查 config.json 与权重文件”

更推荐：

- “当前模型资源不完整，建议重新下载”

不推荐：

- “推理服务启动失败”

更推荐：

- “语音生成服务暂时没有成功启动，你可以重试或导出日志以便排查”

## 12. 交互原则

### 12.1 小白优先

- 默认路径只保留必要操作
- 不把复杂参数堆到首屏
- 不要求用户理解下载源、模型路径、服务进程

### 12.2 状态透明

- 用户必须知道系统“正在做什么”
- 用户必须知道“还要等多久”
- 用户必须知道“失败后能怎么办”

### 12.3 创作导向

- 主界面更像创作工具，而不是系统工具
- 结果试听和导出应该有足够的存在感
- 输入体验要比“设置体验”更重要

## 13. 给设计师的优先交付建议

如果设计资源有限，建议先按这个优先级出稿：

1. 初始化流程全套
2. 声音克隆页
3. 素材生成历史页
4. 设置页

如果只能先做一部分，建议先做：

- 初始化流程
- 声音克隆页
- 素材生成历史页

因为这三部分最影响首发体验和前端开发推进。

建议设计师最终交付：

- 信息架构图
- 关键用户流程图
- 初始化流程低保真
- 主界面高保真
- 状态设计页
- 组件规范页
- 颜色 / 字体 / 间距基础规范

## 15. 当前前端实现状态说明

为了方便设计师理解当前项目进度，这里说明一下：

目前工程中已经存在一版 `P0` 前端骨架，主要用于联调与结构验证，包含：

- 主界面骨架
- 状态卡片
- 最小任务面板
- 深色基础样式

但这套页面还不代表最终视觉方案，设计师无需被当前实现样式限制。

可以把当前前端代码理解为：

- 信息结构参考
- 状态层级参考
- 联调占位参考

而不是最终 UI 定稿。

## 16. 结论

`Voca` 的前端设计重点，不是做一个“炫酷的 AI 页面”，而是做一个：

- 对普通用户足够友好
- 对初始化过程足够透明
- 对失败恢复足够明确
- 对声音克隆工作流足够顺滑
- 对历史回看和复用足够高效
- 对结果试听和导出足够直接

如果设计师优先把“初始化流程”“声音克隆页”“素材生成历史页”设计好，后续整个产品的可用性会大幅提升。
